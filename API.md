# Paper trading prototype contract

Local multi-account prototype. Synthetic demo quotes only: never claim live exchange data. No broker order integration. Flask 3 serves the React/Vite build and JSON API on localhost:8000. OIDC login and account scoping are configured as described in [AUTH0_SETUP.md](AUTH0_SETUP.md).

`GET /auth/login` redirects to the configured OIDC provider; `GET /auth/callback` completes sign-in. `GET /api/auth/me` returns `{authenticated:true,user:{id,display_name,subject},csrf_token}` for a valid session and 401 otherwise. `POST /api/auth/logout` revokes the server-side session. All other account and catalogue APIs require the opaque HttpOnly `paperlane_sid` cookie; protected POST routes also require the `X-CSRF-Token` header from `/api/auth/me`. The user ID or account schema is never accepted from request data. `/api/health` remains public. Provider access tokens are not sent to the browser.

Amounts are INR. Timestamps ISO UTC. Option metadata is illustrative. Activated cash listings carry dated catalogue metadata, exchange, display_symbol, tick_size, catalogue_id and synthetic price provenance. Account initially INR 1000000 virtual funds.

GET /api/state returns {mode:"SIMULATED", market_status:"DEMO SESSION", updated_at, account:{initial_balance,cash,equity,available_margin,used_margin,realized_pnl,unrealized_pnl}, instruments:[{symbol,name,kind:"EQUITY"|"INDEX"|"OPTION",underlying,option_type:null|"CE"|"PE",strike:null|number,expiry:null|string,lot_size,ltp,bid,ask,change_pct}], positions:[{symbol,quantity,average_price,ltp,unrealized_pnl}], orders:[{id,symbol,side:"BUY"|"SELL",type:"MARKET"|"LIMIT"|"STOP_LIMIT",quantity,limit_price,trigger_price,triggered,status:"FILLED"|"PENDING"|"CANCELLED"|"REJECTED",filled_price,fee,created_at,message}], trades:[{id,symbol,side,quantity,price,fee,created_at}], history:{[symbol]:[{time,value}]}}.

`GET /api/state` also returns `history_mode` (`snapshot` or `delta`) and `history_cursor` (UTC ISO timestamp). The first request omits `history_after` and receives a complete retained chart snapshot. Pass the last `history_cursor` as `history_after` on subsequent polls; then `history` contains only newer points while account, quotes, orders and positions remain current. An empty `history` means no new samples. If the cursor is beyond the retained 1,800-point window or ahead of the server, the API sends `history_mode:"snapshot"` again and the client replaces its chart history. Invalid timestamps return 400. This keeps old clients compatible while reducing repeated chart payloads.

POST /api/orders body {symbol,side,type,quantity,limit_price?,trigger_price?} returns {order:...}; quantity is units (must be a whole instrument lot multiple). MARKET fills at ask for buy and bid for sell. LIMIT waits for a matching future quote, not last price. Index itself not tradable. Return 400 {error:string} for invalid input. Insufficient capital/margin produces a rejected order or error with explanation. Pending orders reserve funds/margin conservatively.

POST /api/orders/{id}/cancel returns {order:...}. POST /api/reset body {} resets account and records. POST /api/journal body {text} persists a note and returns {notes:[{text,created_at}]}. GET /api/journal returns {notes:[...]}. GET /api/health returns {ok:true,mode:"SIMULATED"}.

GET /api/report reconstructs all stored fills using weighted-average cost and prorated entry/exit fees, without writing to the account. Returns {summary:{gross_pnl,total_fees,net_realized_pnl,closed_net_pnl,open_entry_fees,fill_count,open_position_count},closed:[{symbol,direction:"LONG"|"SHORT",quantity,entry_price,exit_price,entry_at,exit_at,gross_pnl,fees,net_pnl}],fills:[{...trade,effect}]}. Closed portions and fills are newest first; entry_at is the initial opening timestamp of the average-cost position. net_realized_pnl = gross_pnl - total_fees = closed_net_pnl - open_entry_fees. Values are rounded for display, not during allocation. Unlike the state preview, the report is not limited to 300 fills.

Quote engine runs on server in demo mode independent of browser. Backend PostgreSQL persistence with a Liquibase-managed schema. Use conservative clearly labelled estimated margin for short options/equity; no claim of exchange SPAN accuracy. Fee model disclosed as illustrative. Expiry settlement, partial fills, real historical replay and live data deferred, clearly documented. UI polls every 2s and shows offline status if requests fail. On stale/unavailable quotes backend must refuse fills.

GET /api/catalogue?q=&exchange=ALL|NSE|BSE&offset=0&limit=40 returns {items,total,offset,limit,coverage}. Items contain id, exchange, trading_symbol, name, series, isin, instrument_type, lot_size, tick_size, buy_allowed, sell_allowed, can_simulate and restriction. Coverage includes source URL, docs, source_sha256, retrieved_at and NSE/BSE counts. The endpoint searches the entire local snapshot, independent of active instruments.

POST /api/catalogue/activate body {id} lazily activates an eligible entry and returns {symbol,instrument}. Repeated activation reuses the instrument; legacy stocks retain existing identifiers/history. Max 100 active instruments. Quotes are arbitrary synthetic values; view-only entries cannot activate.

STOP_LIMIT requires positive finite trigger_price and limit_price aligned to tick_size. BUY limit >= trigger; SELL limit <= trigger. Last price triggers BUY at >= trigger or SELL at <= trigger; subsequent executable bid/ask must satisfy the limit. Reservation begins on submission and is released on cancellation. Orders can remain pending after a price gap. Existing databases migrate trigger fields without resetting fills.

Stock option APIs are documented in data/OPTIONS.md. GET /api/options?symbol=<active-symbol-or-catalogue-id>&expiry=YYYY-MM-DD returns {mode,underlying,expiries,expiry,contracts,notes,coverage}. POST /api/options/activate {id} returns {symbol,instrument}. State history retains up to 1,800 observed synthetic ticks per symbol.

## Guided trade plan and cost estimate

GET /api/learning returns saved `plans`, each with an integer `id`, `symbol`, `reason`, `exit_plan`, `max_loss`, `confidence`, and `created_at`. POST /api/trade-plan creates a plan; it does not place an order or enforce a stop.

POST /api/order-preview body `{symbol,side,quantity,plan_id?}` returns the current synthetic `quote_price`, `estimated_trade_value`, `estimated_entry_fee`, `estimated_full_spread_cost` for an immediate buy and sell, `plan_max_loss`, and a plain-English limitation. The plan must belong to the same symbol. The estimate does not reserve funds or execute anything.

POST /api/orders also accepts optional integer `plan_id`, validated against the order symbol. Orders and their fills retain this association. New fill rows include `order_id` and `plan_id`; older rows have null values after additive SQLite migration. GET /api/report closed rows include `entry_trade_id`, `exit_trade_id`, `plan` and `plan_link_status` (`recorded`, `unavailable`, or `ambiguous` when a position contains entries linked to different plans). A recorded plan is evidence of what the user wrote, not proof the user followed it. Planned loss is a budget, not a guaranteed maximum.
